Прогнозирование дефолта по кредитным картам — ML Pipeline

End-to-end ML-проект для прогнозирования вероятности дефолта клиентов по кредитным картам. Проект охватывает полный цикл разработки ML-модели: от подготовки и валидации данных до обучения, отслеживания экспериментов, тестирования и развёртывания модели через FastAPI и Docker.

1. Описание проекта

Задача: бинарная классификация — прогнозирование вероятности дефолта клиента по кредитной карте в следующем месяце.

Датасет: Default of Credit Card Clients Dataset.

30 000 наблюдений;

23 исходных признака;

целевая переменная: default.payment.next.month;

0 — дефолт отсутствует;

1 — дефолт произошёл.

2. Используемые модели и результаты

В рамках проекта были обучены и сравнены две модели классификации:

Logistic Regression;

Gradient Boosting Classifier.

Для обеих моделей использовались конвейеры обработки данных Scikit-learn и подбор гиперпараметров с помощью GridSearchCV и стратифицированной кросс-валидации.

4. Подготовка и валидация данных

Этап подготовки данных включает:

Загрузку исходного датасета.

Проверку типов данных, пропусков и дубликатов.

Проверку допустимых диапазонов значений признаков.

Валидацию данных с использованием Great Expectations.

Генерацию дополнительных признаков.

Стратифицированное разделение на обучающую и тестовую выборки.

В процессе Feature Engineering были созданы дополнительные признаки:

DELAY_COUNT — количество месяцев с просрочкой платежа;

MAX_DELAY — максимальная величина просрочки;

AVG_POSITIVE_DELAY — средняя величина положительных значений просрочки;

AVG_BILL_AMT — средний размер счёта;

MAX_BILL_AMT — максимальный размер счёта;

AVG_PAY_AMT — средний размер платежа;

AGE_GROUP — возрастная группа клиента.

5. Обучение моделей

Для обучения используется Scikit-learn.

Основные этапы:

Предобработка данных с помощью ColumnTransformer.

Заполнение пропусков через SimpleImputer.

Масштабирование числовых признаков через StandardScaler.

Кодирование категориальных признаков через OneHotEncoder.

Подбор гиперпараметров с помощью GridSearchCV.

Стратифицированная кросс-валидация.

Оценка качества моделей по ROC-AUC, Precision, Recall и F1-score.

Обученные модели сохраняются в директории models/.

6. Отслеживание экспериментов — MLflow

Для отслеживания экспериментов и результатов обучения используется MLflow.

В MLflow сохраняются:

Гиперпараметры моделей.

Метрики качества.

Обученные модели.

Артефакты, включая графики оценки качества.

Для запуска интерфейса MLflow:

mlflow ui

После запуска интерфейс доступен по адресу:

http://127.0.0.1:5000

7. Версионирование данных и ML Pipeline — DVC

Для версионирования данных и управления этапами ML Pipeline используется DVC.

Pipeline состоит из двух основных стадий:

prepare — подготовка данных и генерация признаков.

train — обучение моделей и оценка качества.

Запуск всего pipeline:

dvc repro

Проверка состояния pipeline:

dvc status

Отображение графа зависимостей:

dvc dag

В текущей конфигурации используется локальное хранилище DVC без настроенного облачного remote.

11. Мониторинг дрейфа данных

В проекте планируется реализация мониторинга Population Stability Index (PSI).

Метрика PSI используется для сравнения распределений признаков между эталонной выборкой и новыми поступающими данными. Это позволяет выявлять потенциальные изменения характеристик клиентской базы.

Раздел будет дополнен после реализации компонента мониторинга.
